# 主体与信息冲突调查合同

冲突是研究任务，不是停止条件。只要存在公司名、人名、域名、邮箱域名、电话、地址、项目、附件或其他可检索锚点，就继续搜集并解释冲突。

## 候选实体矩阵

对每个候选分别记录：原始称呼、展示名、法定名、域名、国家、注册号、电话、地址、人员、社媒、项目、来源时态、支持锚点、冲突锚点和当前裁决。不得把多个候选的项目、财务、人员或风险混入目标 Company。

裁决使用：

- `accepted_target`：强锚点闭合到询盘目标；
- `possible_related`：可能是旧站、品牌、关联方、分支、迁移域名或同一经营团队；
- `homonym_rejected`：纯同名/近名，强锚点冲突；
- `impersonation_suspected`：询盘联系方式借用或仿冒真实主体；
- `unresolved`：证据不足，继续保留。

## 强制关系假设

遇到名称或域名冲突时至少检验：

1. 同一主体的新旧域名或网站迁移；
2. 法定名、品牌名、缩写或 `&`/`and`/字母连写差异；
3. 母子公司、分支、关联公司、SPV、加盟或共同控制；
4. 历史主体注销后由新主体继续经营；
5. 供应商数据库把同名公司错误合并；
6. 纯同名且国家、地址、电话、人员无交集；
7. 冒名、钓鱼或相似域名仿冒。

## 调查瀑布流

逐候选执行并保存 no_result：

1. 官方网站 footer、About、Contact、Privacy、Terms、招聘、PDF、图片元数据和站内链接；
2. 国家/省州登记、牌照、税号、政府采购、许可、法院和公告；
3. RDAP/WHOIS、DNS、MX、证书透明度、网页存档、旧站跳转和域名注册时间；
4. 电话、地址、邮箱、人名与域名的精确组合搜索；
5. LinkedIn、Facebook、Instagram、YouTube、地图和行业目录，核对历史名称与链接；
6. 项目业主、开发商、总包、顾问、分包和供应商反查；
7. TradeWind 与其他 Provider 分别查询精确域名、法定名、展示名和历史别名，宽结果逐条仲裁；
8. 询盘附件、邮件头、签名、名片、文件属性和客户补件。

## 结论边界

- 单一 Provider 0 结果不支持“公司不存在”。
- 多个弱来源一致不替代一个强身份锚点。
- 冲突未解时可以完成广度/深度报告和证据型准备度评分，但身份维度只按已证实 component 给分。
- 互斥强身份或冒名信号分别加入 `identity_conflict`、`fraud_or_impersonation_signal` hard block；限制报价、授信和总体分数，不限制继续检索。
- 报告必须说明最可能关系、替代解释、支持/反证及下一条最有信息增益的查询。
